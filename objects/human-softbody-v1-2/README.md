# Human Soft Body V1.2 — Quest performance and limb grabbing

Owner reported 2–3 FPS and unresponsive joint grabs in V1.1. Source audit: old CPU solver evaluated 10,602 edges + 7,236 volumes 3 times per 120 Hz substep (6,421,680 evaluations per nominal second), 2,831 skin samples × 27 neighbouring hash cells × 2 contact passes × 120 Hz (18,344,880 lookups per nominal second), plus tether work, per-contact Jacobians, full mesh position interpolation and normal reconstruction. At 3 callbacks/s, max 3 × 1/120 s per callback = 7.5% real-time simulation.

V1.2 keeps the exact published GLB and original 22-bone SkinnedMesh. Native GPU skinning updates only bones; GPU vertex shader adds interpolated cage offsets (31,568 bytes per update) and uses skinned normals. No main-thread full-mesh position upload or normal recomputation. Original material/texture retained in rigid diagnostic; node material copies original base color, texture, roughness, metalness and sidedness in tissue mode. WebGPU rendering resolution scale .55. Rigid simulation 60 Hz, 8 solver iterations, collision groups and joint constraints retained; CCD on head/hands/feet. Dedicated worker owns the actual cage solver and sends transferable result buffers; one job maximum in flight, no backlog, adaptive requested rate 5–20 Hz. One constraint iteration, 737 stratified surface samples, topology exclusions remapped; pressure and skin contact remain approximate, coarser than V1.1. No tissue reaction impulses into skeleton, no guarantee against surface intersection. GPU shader compilation fallback disables tissue if necessary.

Trigger grabbing uses analytic ray-vs-limb proxy selection, direct XR input-source poses, select events and gamepad polling/retry. Turquoise marker shows selected target, status identifies bone. Mass-scaled bounded PD acceleration with gravity compensation, lever arm near joints, and 3 m/s target speed limit. Zelda side grips and sticks unchanged. This is an improved interaction implementation, not a hardware-confirmed fix.

Actual model cage microbenchmark, identical 20 solver steps in the tool runtime (not Quest): V1.1 146.85 ms/step at nominal 120 Hz; V1.2 29.8 ms/step at nominal 20 Hz. These are single-run timings, not browser or headset frame rates. At nominal rates CPU tissue work falls about 29.6×. Actual cage pressure test: 7.97 mm local indentation, 99.985% cage volume, no inverted tetrahedra in that test, zero residual after release. Worker logic tested using actual 22 joint rest transforms and 1,973 nodes with 30 prescribed poses, mocked worker transport; all offsets finite, reset epoch correct, 616-byte pose message and 31,568-byte result. Real browser worker, shader, full articulated drop and physical Quest controller testing remain outstanding. No guaranteed FPS. Diagnostics show callback FPS, rigid update time, last worker computation time and render submission CPU time (not GPU completion time).
